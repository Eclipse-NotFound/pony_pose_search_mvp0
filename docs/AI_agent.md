# AI Agent 总控文档（Master Instruction）v1.0

## 1. 文档目的

本文件是本项目所有 AI agent 的最高级开发说明。

任何 AI agent（包括 ChatGPT、Claude、Gemini、Codex、Zcode 等）在参与本项目开发前，应首先阅读本文件，并严格遵守其中规定。

本文件用于统一开发原则、模块边界、接口规范、工作流程和交付要求，避免 AI agent 在开发过程中出现越界开发、接口漂移、重复实现或擅自修改架构等问题。

若无特殊指令，严禁更改本文件。

---

# 2. 项目简介

项目名称：

**Pony Pose Search MVP0**

项目目标：

建立一个能够根据姿态图片检索《小马宝莉：友谊是魔法》动画中对应姿势画面的最小可运行系统（MVP0）。

MVP0 的目标不是实现完整产品，而是验证整个姿态检索流程可以顺利运行。

# 6. 项目总体原则

本项目采用严格模块化开发。

原则如下：

1. 一个模块只负责一件事情。

2. 模块不得调用其他模块的私有实现。对于无业务含义的通用工具，只有在至少两个模块出现真实重复后，才允许移入 scripts/common/。不得为了未来可能复用而提前抽象。

3. 模块之间只能通过约定的数据文件交接。

4. 每个模块都应可以单独运行。

5. 每个模块都应可以单独测试。

6. 不允许将多个模块合并成一个大型程序。

# 7.项目指引文件
本项目供AI agent阅读的指引文件存放于
```text
docs/
```
文件夹中。其目录结构和其中文件如下。
```text
docs/
    tasks/
        M01_tasks.md
        M02_tasks.md
        M03_tasks.md
        M04_tasks.md
        M05_tasks.md
        M06_tasks.md
        M07_tasks.md
        M08_tasks.md
        M09_tasks.md
    interfaces.md
    directory.md
    AI_agent.md
```
tasks文件夹中存放各模块任务书，包括要完成的任务和验收清单，如M01_tasks.md
中为编写M01模块时需要完成的任务和其验收清单。

每次任务必须阅读：
1. AI_agent.md；
2. 当前模块任务卡；
3. 任务卡明确引用的 directory.md 和 interfaces.md 条目。

不得读取无关模块的任务卡。

只有在当前模块验收清单全部通过后才允许进入下一模块的开发。

directory.md中为本项目的目录编码和文件命名规范。任何新建的目录，文件的命名格式都应遵循directory.md。

interfaces.md中为本项目全部接口和数据规范。若无特殊要求，本项目的开发应全程遵循interfaces.md。

若无特殊指令，严禁更改项目指引文件

项目范围和 Agent 行为：AI_agent.md 负责。
路径和命名：directory.md 负责。
字段和数据结构：interfaces.md 负责。
当前模块实现及验收：当前任务卡负责。

不同文件不得重新定义其他文件负责的内容。
发生冲突时停止执行并报告，不得自行选择。

# 8. 图形化界面原则

- M02

---

# 9. 数据交互原则

模块之间统一通过文件交互。

允许：

- CSV

- JSON

- PNG

- JPG

不得：

- 数据库

- Redis

- 网络接口

- RPC

- HTTP API

---

# 10. 代码原则

代码要求：

- 清晰

- 简单

- 易读

- 注释适量

- 适合初学者维护

避免：

- 过度设计

- 炫技

- 不必要抽象

- 超长继承链

- 复杂设计模式

- 使用不必要的大型依赖

---

# 11. 输出要求

交付内容应包括：

1. 源代码

2. 必要注释

3. 运行方式

4. 输入说明

5. 输出说明

6. 已知限制（如有）

---

# 12. 最终原则

AI agent 的目标不是“尽可能多地开发”，而是：

- 正确完成当前模块；

- 保持系统稳定；

- 保持接口一致；

- 保持模块独立；

- 为后续模块提供可靠输入。

任何超出当前任务范围的改动，都应先提出建议，等待确认后再实施。
