* 编程能力有限；
* 主要依赖AI Agent完成开发；
* 需要代码结构简单；
* 需要任务边界明确；
* 需要能够逐步验收；
* 不适合维护复杂模型训练系统；

```text

单GPU

```

因此MVP1必须遵循：

```text
优先简单算法
优先成熟库

避免过度抽象
```

## 4. MVP1总体目标

MVP1的目标不是实现完全自动标注。

MVP1的目标是：

> 在保留人工确认的前提下，为M03角色框选和M05关键点标注增加AI或简单算法辅助，从而减少重复操作。

MVP1完成后的目标流程：

```text
视频帧
  ↓
M03人工框选一个起始帧
  ↓
系统自动传播或预测后续角色框
  ↓
人工接受、修正或拒绝
  ↓
M05根据已有关键点、角色框和模板生成关键点建议
  ↓
人工接受、拖动修正或拒绝
  ↓
保存正式关键点
  ↓
M06生成Pose Vector v1/v2
  ↓
M08搜索
```

核心定位：

```text
AI只提供建议
人工决定正式结果
```

## 5. MVP1明确包含的功能

MVP1包含以下三类能力。

### 5.1 M03角色框辅助

在用户已经人工框选一帧后，系统可以预测相邻帧中的角色框。

允许使用：

```text
OpenCV目标跟踪
CSRT
模板匹配
光流
框坐标插值
相邻帧位置传播
简单颜色或轮廓辅助
```

系统输出的框必须是建议框。

用户可以：

```text
接受
修改
拒绝
重新手工框选
```

### 5.2 M05关键点预标注

系统可以根据：

* 已确认角色框；
* 前一帧已确认关键点；
* 后一帧已确认关键点；
* 角色骨架模板；
* 相邻帧图像；

生成当前帧关键点建议。

允许使用：

```text
框内相对坐标映射
前一帧关键点传播
后一帧关键点反向传播
线性插值
仿射变换
稀疏光流
简单角点或边缘吸附
默认骨架模板
水平翻转模板
```

系统不得把建议关键点直接作为正式标注保存。

### 5.3 人工审核闭环

所有自动建议必须经过人工审核。

最小状态：

```text
suggested
accepted
edited
rejected
```

含义：

```text
suggested
系统已生成建议，尚未确认

accepted
用户直接接受建议

edited
用户修改后接受

rejected
用户拒绝建议
```

只有：

```text
accepted
edited
```

才能进入正式标注数据。

## 7. 核心设计原则

### 7.1 正式数据与AI建议隔离

AI建议不得直接写入现有正式标注文件。

建议文件和正式文件必须分离。

建议路径示例：

```text
suggestions/
  {character_id}/
    {episode_id}/
      bbox_suggestions.json
      keypoint_suggestions.json
```

正式数据继续使用现有M03和M05路径。

不得为了方便覆盖正式数据。

---

### 7.2 建议文件必须可删除

建议文件属于派生数据。

删除后应能够重新生成。

正式标注属于人工资产，不得因重新运行AI建议而改变。

---

### 7.3 AI建议必须记录来源

每条建议至少记录：

```text
method
source_frame_id
target_frame_id
confidence
status
created_at
```

示例：

```json
{
  "method": "csrt_tracking",
  "source_frame_id": "s01e15_f000100",
  "target_frame_id": "s01e15_f000101",
  "confidence": 0.84,
  "status": "suggested"
}
```

关键点建议还应记录：

```text
source_keypoints
source_bbox
target_bbox
```

或能够追溯到对应来源文件。

---

### 7.4 算法必须可替换

M03和M05不能直接依赖某个具体算法的数据结构。

建议统一接口。

例如M03：

```python
suggest_bbox(
    source_frame,
    target_frame,
    source_bbox,
    settings
) -> BBoxSuggestion
```

M05：

```python
suggest_keypoints(
    source_frame,
    target_frame,
    source_bbox,
    target_bbox,
    source_keypoints,
    schema,
    settings
) -> KeypointSuggestion
```

算法实现可以替换，但输出结构保持稳定。

---

### 7.5 失败必须可恢复

算法失败时：

```text
不得破坏正式数据
不得保存空正式标注
不得自动跳过并假装成功
不得阻止用户手工继续
```

系统应明确显示：

```text
建议失败
请人工标注
```

---

### 7.6 默认流程仍允许纯人工

MVP1完成后，用户仍应能：

```text
完全不用AI辅助
直接按MVP0.6方式手工完成M03和M05
```

AI辅助是可选功能，不得成为强制依赖。

## 9. M05关键点辅助推荐方案

M05优先使用：

```text
已有正式关键点
+
角色框相对坐标映射
+
相邻帧传播
+
人工修正
```

### 基础映射

假设源框为：

```text
source_bbox
```

目标框为：

```text
target_bbox
```

先把源关键点转换为源框内相对坐标：

```text
relative_x
relative_y
```

再映射到目标框。

这种方法必须作为基础回退方案。

### 可选修正

基础映射之后，可以增加：

```text
光流修正
局部模板匹配
角点吸附
边缘吸附
```

但任何修正都必须限制在合理搜索半径内。

### 模板初始化

如果当前帧没有可传播的历史关键点，可以使用：

```text
schema默认骨架模板
```

模板只用于预放置。

用户仍需人工调整。

### 遮挡处理

简单算法不得擅自判断所有遮挡。

当无法可靠判断时：

```text
保持available=false
或标记为needs_review
```

不得伪造高置信度关键点。

### 腿部身份

前后腿、不同腿槽位容易因交叉和遮挡混淆。

MVP1中：

```text
算法可以预测位置
人工必须确认腿身份
```

不得根据最近距离自动确定最终腿ID并直接保存。

## 10. M05与Pose Vector的边界

M05负责：

```text
关键点坐标
关键点available
人工确认状态
```

M05不得直接计算或修改：

```text
Pose Vector v1
Pose Vector v2
方向权重
相似度分数
腿部无序配对
```

正式关键点保存后，仍由M06生成数据库姿态向量。

查询姿态仍由M07处理。

MVP1不得把M05和M06合并。

## 20. 停止条件

出现以下情况必须停止：

* 需要训练大型模型；
* 需要修改M06/M08核心算法；
* 需要改变Pose Vector格式；
* 需要修改schema；
* 需要让AI建议直接覆盖正式标注；
* 需要引入数据库或服务端；
* 简单算法无法达到可用效果；
* M03或M05现有结构无法安全扩展；
* 原432项测试无法保持；
* 必须破坏MVP0.6兼容性。

停止时应报告事实和最小替代方案，不得自行扩大项目。
