# 姿态标注口径

2026-10-11 复盘后的现行补充见[方向优先的数据格式与标注规则](pose-record-v1.md)。以下保留历史决定与实验接续；新格式、左右翻转、辅助视角/位置及工程完整角色规则以该补充为准。

## 尾巴初始朝向

来源：用户于 2026-09-11 在接手标注会话中明确说明：

> 我个人把尾根标注为尾巴与身体的连接方向，尾尖不标在特定位置而是与尾根一起表示尾巴的初始朝向（即不考虑尾巴的下垂等）

标注按这一含义执行：`tail.tail_base` 与 `tail.tail_end` 组成从身体向外的初始朝向。前者作为连接处附近的起点，后者作为该方向的参考点，不要求对应真实尾巴末端。判断近根处尾束刚伸出的方向，不追随后续弯曲或重力下垂。

真实尾尖被遮挡或在画面外，不自动使朝向参考点不可用；重点是能否辨认初始方向。连接处或方向只能估计时，在草稿中注明，交用户审核。

保留现有字段名及向量计算规则；预览用“尾部朝向参考点”解释 `tail_end`。本次仅修正待审草稿，不视为用户已确认具体坐标，也不批量重写历史正式标注。

## 头与颈的方向参考点

来源：2026-09-11 用户确认“是方向参考点”。

- `head_center → head_front` 表达头的朝向。`head_front` 不必贴在鼻尖。
- `body_1 → neck` 表达颈部朝向。`neck` 不必落在可见颈部的几何中心。
- 标注优先参照用户已有人工样本，结合当前帧的姿势确定方向；不机械平移相邻帧的全部坐标。

## 腿部中间点与遮挡

来源：2026-09-11 用户认可“腿的结构和走向清楚时允许近似放点；整段被遮挡、无法判断时留空”。

直腿或简化动画轮廓上没有清晰关节折线时，可按结构与走向近似放置中间点。完全遮挡且无法判断的点留空；已能确定的其他点仍可标注。优先沿用人工参考中的腿段连接次序：前腿 `base → mid → end`，后腿 `base → knee → mid → end`。

## 参考样本与审核边界

优先找同集、同镜头、相近姿势的非空人工标注，再用其他姿势样本核对一致口径。时间最近只是筛选参考的线索，不保证姿势相同。49条正式记录中有1条全空记录，不能用作落点参考。

用户确认的是标注口径，尚不等于确认各帧的具体坐标。代理生成或修订的点始终保留待审核状态，直到用户确认对应帧。当前明确口径优先于少数历史异常点；不自动修改这些历史点。

## 腿根与后躯中心

来源：2026-09-12 用户针对首张试标（第15集23秒）说明：前腿2的腿根应像前腿1一样，放在腿与身体连接区域的中间；后躯中心向右上调整，放在两条后腿连接处之间。

后续标注沿用上述位置含义，并结合当前帧姿势判断，不把“向右上”机械套用到其他朝向的角色。用户可在预览中点选具体坐标；点选位置用于修订草稿，是否纳入正式数据以该帧的审核结论为准。

## 2026-10-08：方向优先的表示方式讨论（尚未实施）

用户提出：系统实际关心身体与肢体的方向向量，希望视觉模型直接标注方向；关键点可以只留作人工查询工具，或不再作为必需数据。这是优化方向的讨论，尚未确定替换模型或删除数据。

已核对的程序事实：`pose_vector_utils.unit_direction` 丢弃线段长度，只保留二维单位方向；当前 v3 点位规则形成14个方向（头、颈、身体、尾巴各1；两前腿各2；两后腿各3）。`search_similar_poses.direction_similarity` 只比较方向，v2 检索已支持方向级可用性及同类两腿的整条配对。当前训练脚本仍使用 YOLOv8-Pose 的21点输出，改为直接方向预测需要适配训练标签、模型输出、训练误差计算及审核流程，不能仅改字段名。

AI建议，待用户决定：将方向及“能否判断”作为检索所需数据；图上箭头位置可以是可选的展示信息，关键点输入也可先转换成方向。沿用当前画面内二维方向及各腿分段，不将一条腿压成一个方向。已有点位与原图保留，转换成方向时继承原审核状态，草稿不能因转换自动成为正式数据。新方向标注无法凭方向唯一还原原图关节位置和身体比例。

待验证：直接预测方向能否改善本项目的方向误差、检索结果和人工审核耗时。用独立镜头作对照，避免把相邻几帧分别当作训练和独立验证。此轮只做代码核对和可行性讨论，未训练新模型、修改运行代码或改动正式标注。

可接处：确定先改箭头审核与数据入口，还是优先做直接方向预测的模型对照。推荐先让数据与审核接受方向，保留原模型作为可比较、可回退的来源。
