# 方向优先的数据格式与标注规则

> 2026-10-13：本文保留中间格式及历史复盘。日常编辑和检索已改为多物种共同库，旧 `search_pose_records.py` 命令转到 M08；现行操作见[共同流程指南](module-workflow.md)。

2026-10-11。本版依据用户在本轮复盘确认的五项选择；概念见 [CONTEXT.md](../CONTEXT.md)，选择及实施记录见[复盘](../设计/复盘-2026-10-11-数据算法与标注规则.md)。历史记录与历次实验见 [annotation_conventions.md](annotation_conventions.md)。

## 1. 从什么变成什么

原来主要是“某集某帧的21个点 → 14个方向”。新格式直接保存方向，也保留需要的证据：它属于哪个角色实例、来自哪张图片或工程、谁作出的判断、是否审核、哪个部位看得见、能否从工程取得完整角色。点位是可选信息；直接方向模型不需要先伪造一套点。

一条记录表示**一个角色实例在一个画面中的一份标注版本**。同一画面有不同标注或新修订时保留不同记录，不用后来的预测覆盖人工记录。原有正式标注和实验记录分别转换，不拼成一个“都已审核”的训练集。

| 信息 | 当前字段与含义 |
|---|---|
| 记录与样本 | `record_id` 标识标注版本；`sample_id` 标识被标注样本 |
| 语义与格式 | `schema_version=pose_record_v1` 管存储格式；`pose_definition_id=pony_body14_v1` 管方向含义，二者分开 |
| 角色 | `subject.character_id`、`form_id`、`body_profile_id`、`instance_id`、可选 `track_id` |
| 来源 | `source.kind`、原图及指纹、剧集/画面/时间、可选绝对帧号与时间基准、工程场景及元件实例路径 |
| 坐标 | `coordinates` 明示图像像素、向右/向下为正、图像尺寸、可选返回来源画面的变换 |
| 标注证据 | `annotation.origin`、审核状态、源标签文件及指纹、方法、备注 |
| 方向 | `directions` 中的14个单位向量；逐项保存依据、可见性、缺失原因、可选置信度 |
| 视角 | `view.body` 与 `view.head` 分开；未标注保持 null |
| 相对位置 | `layout`：以身体中点为原点、前后连接中心距离为尺度；可选头部中心、两前蹄中心、两后蹄中心 |
| 校准和审核 | `reference_points` 可省略；有时保存旧点位，供重算或显示 |
| 工程可取得性 | `asset_access.complete_character` 和确认依据 `evidence_ref` |
| 腿的身份 | `leg_identity` 保留能辨认的近远侧、身体左右侧或工程路径；槽位1/2不冒充这些身份 |
| 可选部位 | `optional_parts.wings.present` 保存有无翅膀，翅膀姿态未标就保持空；身体14方向不凭形态自动生成翼姿 |
| 数据分组 | `dataset_groups` 保留剧集、镜头和复用素材族；未知分组不虚构。实验快照另保留原切分和权重 |

旧记录转换不能补回原本不存在的信息：旧空值不自动变成“遮挡”，旧时间秒数不硬凑绝对帧号，未知视角不由角色朝左/朝右推断，模板同名不证明角色身份。

## 2. 14个方向怎样标

| 部位 | 方向 | 核对要点 |
|---|---|---|
| 头 | 头部中心 → 朝向参考 | 朝向参考不必在鼻尖；不追随眼球看向哪里 |
| 颈 | 前躯连接中心 → 颈部朝向参考 | 参考点用于表达颈的方向，不要求是几何中心 |
| 身体 | 前躯连接中心 → 后躯连接中心 | 方向由前向后；后躯中心在两后腿连接区域之间 |
| 尾 | 连接区域 → 向外初始朝向 | 不追随下垂和卷曲，不要求点到真实尾尖 |
| 每条前腿 | 腿根 → 中间转折；中间转折 → 蹄端 | 腿根在身体连接区域中间；直腿可按清楚的结构近似中间位置 |
| 每条后腿 | 腿根 → 上转折 → 下转折 → 蹄端，共3段 | 对应旧 base/knee/mid/end 的次序；不把动画绘制转折冒称精确的生物学关节 |

箭头起点在审核图上可以挪动以便看清，方向数据不因此改变。若移动的是用于计算的参考点，则重新计算方向，并作为标签修订保留。箭头显示长度不表示肢体长短，也不表示置信度。

方向只描述当前画面中的二维投影，不从一张侧身图补出三维角度。身体歪斜、上下倒置仍保留其在画面中的方向；本轮只增加可选左右翻转，不自动旋正角色。

## 3. 不确定、看不见、没标，不是一回事

每个方向分别记录：

- `value`：已判断的单位向量，或 null；零向量、NaN、无穷值不能充当有效方向。
- `support`：直接观察 `observed`、结构近似 `inferred`、工程几何 `asset_geometry`、旧参考 `legacy_reference`、未知 `unknown`。
- `visibility`：在当前图片中可见、遮挡、画面外、未知，或不适用。
- `missing_reason`：无方向时写未标注 `not_annotated`、无法辨认 `not_discernible`、遮挡 `occluded`、画面外 `out_of_frame`、无此部位 `not_applicable`、工程未绘出 `not_drawn`、几何无效 `invalid_geometry`，或旧记录未说明 `legacy_unspecified`。
- `confidence`：只有确有依据时填写；缺失保持 null。训练时给 AI 标签的0.5权重不是“有50%把握”，不能抄到这里。

“结构和走向清楚时允许近似放点”仍有效。拿不准方向时留空，不为了凑齐14项强行填。来源、审核状态与可见性独立：代理画得清楚不等于用户审核，人工留空也不自动等于遮挡。

用户确认：**对应图层里有完整角色，即按完整处理。** 实施为：确认该帧中能取得完整角色后记录 `complete_character=verified`，附查看或导出依据；有工程依据的隐藏方向可以参与检索。只见部件名、模板里有一条腿，或知道它在身体后面，都不能自动填入这个确认。

完整角色可取得，不等于所有方向已经提取成功。缺少方向数值时继续保持缺失。成片中的可见性也继续保存：训练图若仍是被桌子遮挡的合成画面，不能把隐藏方向当作“图片里可直接看见”的监督；需要选择相应的完整角色导出图，或明确另做遮挡推断实验。

## 4. 视角和相对位置先保持轻量

身体与头分别可选正面、斜前、侧面、斜后、背面；分不清就保持未知。这是粗分类，不假装已知道精确三维角度，俯仰等更细分类暂未加入。

相对位置先复用可靠的已有点：头相对身体的位置，以及两前蹄、两后蹄各自的中心。一个腿组只有一只蹄可判断时，不把它冒充“两蹄中心”。身体轴过短、尺度不可靠时不计算这一项。

腿组中心不依赖腿1/腿2排序，因此不会在允许整腿交换时偷偷引入另一套相矛盾的逐腿对应。更细的单蹄位置、脚底朝向和身体压缩参数可以以后独立验证，不在本版强制增加人工工作。

## 5. 当前两条检索入口

**原 M08/M10** 已修复方向级权重及不等数量腿的配对，加入左右翻转开关（默认关）。整条腿一致对应，候选的一条腿不能同时充当查询的两条腿。结果 CSV 新增 `mirrored`，原 HTML 通过匹配说明标出翻转。

**新记录检索** `scripts/m08/search_pose_records.py` 可直接读取方向记录，支持跨角色的同身体结构比较、角色/形态筛选、工程完整角色依据及辅助信息。它是可运行的独立入口，尚未整体替换旧 M10 的数据入口。

新入口默认以方向得分为基础，视角差异最多扣0.10，相对位置差异最多扣0.05；未知项跳过，并报告实际比较了几项。这些数值是透明的初始试用参数，尚未经用户检索偏好校准，分数不是概率。两项扣分上限之和限制在0.25以内，避免辅助信息主导结果。

左右翻转时，方向和相对位置一起翻转，保留原素材与原标签；相同分数优先不翻转。左右翻转与整腿交换是不同操作。

新入口默认使用已审核或既有正式记录；实验待审记录需要显式加入，不能因格式转换混进正式索引。旧 `legacy_official` 表示原文件中的正式身份，不代表本轮重新逐点审核。

## 6. 如何使用本轮产物

隔离转换输出在 `experiments/schema_review_20261011/migrated/`：

- `official_records.jsonl`：49条既有正式记录，其中1条全空。
- `experimental_records.jsonl`：335条旧实验快照，48条原人工参考、287条待审代理记录；与上一文件有重复来源，不能直接合并计样本量。
- `queries/`：两条旧查询的转换结果。
- `migration-report.json`：转换计数、缺图、来源指纹及派生数据核对。

从项目根使用可用 Python 运行：

```text
python scripts/dataset/migrate_pose_records.py
python scripts/m08/search_pose_records.py --query experiments/schema_review_20261011/migrated/queries/query_002.json --database experiments/schema_review_20261011/migrated/official_records.jsonl --output experiments/schema_review_20261011/query002-results.json
```

允许翻转时另加 `--allow-mirror`。读入原有部位权重时加 `--runtime-config config/runtime_settings.json`。允许待审记录参与试验时另加 `--include-unreviewed`。

旧查询001声明的图片已缺失；查询002的图片虽存在，却是纯色底图。留存点位仍可用于方向计算，但两者都无法看原图核验。对照页将查询002画成明确标注的点位示意，没有恢复或替换原图。新查询各自保存图片；旧共享图片只有被该查询明确引用时才读取，并在后续保存时复制为本查询专属图片。

## 7. 下一阶段的评估规则

先留出未用于调整算法的镜头和查询，再看前几名是否有用户愿意使用的素材；同时报告各部位方向误差、缺失/可取得性判断，以及审核劳动。按镜头分组，必要时按复用素材族分组，不能把邻帧数当成独立姿态数。

本轮独角兽真实数据完成转换及检索；公主形态字段、可选翅膀和工程完整角色规则完成合成用例检查。尚未建立经过核对的真实 FLA 方向标签，也未证明公主形态识别质量或真实检索效果提升；不据此删除关键点模型或宣布某模型优胜。
