# 1. 任务目标

读取 M05 人工关键点标注，根据样本的 `keypoint_schema_id` 和对应 `vector_rules`，生成可供 M08 使用的单位方向向量。

流程：

```text
keypoints JSON
↓
读取对应 keypoint schema
↓
计算单位方向向量
↓
生成 pose_vectors JSON
```

M06 只负责姿态向量生成。

不得实现：

* 关键点标注或修改；
* 查询姿态标注；
* 相似度搜索；
* GUI；
* 自动补点；

3. M07 查询姿态向量生成代码；
4. M08 相似度计算代码；
5. 与后腿方向权重有关的测试；
6. 必要时更新相关接口文档中的示例。

## 代码检查要求

不得只修改 JSON 后直接报告完成。

请检查 M06、M07、M08 是否：

1. 从当前 `keypoint_schema_id` 对应的 `direction_weights` 动态读取权重；
2. 没有写死 `0.333`、`1/3` 或三个方向等权；
3. 没有假设前腿和后腿使用相同权重；
4. 没有假设每条腿固定只有两个方向；
5. M06 数据库姿态向量和 M07 查询姿态向量使用完全相同的权重规则；
6. M08 在比较后腿时实际应用 `0.4、0.2、0.4`；
7. 无序腿匹配完成后，仍按各方向对应权重计算得分。

如果代码已经完全动态读取 schema，则不要进行无意义重构，只修改 schema 和必要测试。

## 测试要求

至少增加或更新以下测试：

1. v3 后腿权重读取结果为：

```text
0.4、0.2、0.4
```

2. 权重总和为 `1.0`；
3. v3 前腿权重仍为 `0.5、0.5`；
4. v1、v2 权重不变；
5. M06 使用 v3 后腿权重；
6. M07 使用相同的 v3 后腿权重；
7. M08 相似度计算实际使用新权重；
8. 一个可人工验证的测试案例：

假设三个方向的单项相似度分别为：

```text
1.0、0.0、1.0
```

则加权后腿相似度应为：

```text
1.0 × 0.4 + 0.0 × 0.2 + 1.0 × 0.4 = 0.8
```

9. 所有原有测试继续通过。
