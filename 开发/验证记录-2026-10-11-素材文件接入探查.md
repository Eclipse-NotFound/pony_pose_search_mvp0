# 2026-10-11 素材文件接入探查

用户要求探查 `D:/活/AE/素材/泄露素材` 并规划扩展支持。接续[初探记录](验证记录-2026-10-11-原始动画素材探查.md)，结合已实现的多物种工作台检查接入条件。本文为本轮新执行的结果；[更新方案](../设计/方案卡-2026-10-11-FLA素材利用.md)中的接入阶段尚未实施。

## 实际范围

重新清点全目录；读取所有现代 FLA 主文档，检索多物种库名称；深入读取五个代表 FLA 和一个 Gabby 线索工程。对重复名称的角色文件计算内容指纹，对全部 JPG 读尺寸，对全部 SWF 只读前八字节与路径关联。解码四个 MP4，各抽看五帧，共二十帧；另看两张大 JPG。核对现有姿态库接口及相邻 animate-mcp 的能力边界。

使用现有 Python 3.12.14、Pillow 12.3.0、FFmpeg 9.0.1，没有安装依赖。采用 brainstorming 规划取舍，复用 animate-rigged-character-motion 的只读 XML 检查器。没有制作动画、运行 SWF、打开/转换 FLA、调用原生 Animate、训练模型或写入正式姿态数据。

本轮产物在 [experiments/source_support_20261011](../experiments/source_support_20261011/)，来源文件只读。

## 同名角色文件

`character-name-reuse.json`：638 个角色 FLA 有 561 个不区分大小写的文件名；39 个重复名称组涉及 116 个文件，全部计算了 SHA-256。

- 32 组含不同内容，7 组仅一种字节内容。
- 各组不同内容数相加为 100，不是全目录跨文件名去重总数，也不是 100 套独立绑定。
- `stk_c23_princess_twilight_sparkle.fla` 六份内容全部不同；`stk_c04_applejack.fla` 七份有六种内容。

结论支持“不能按文件名复用校准”。内容不同可能只是局部变化；内容相同也不证明与其他文件没有复用关系。训练分组的素材族另需证据。

## 代表工程复杂性

`representative-capabilities.json` 对以下五个 FLA 读取全部 XML 条目，仅解析 DOMDocument/LIBRARY 场景数据，相关解析错误均为零。

| 工程 | XML 条目 / 场景 XML | 存储的 motion / shape 补间数 | 遮罩图层数 |
|---|---:|---:|---:|
| 823 独角兽暮光模板 | 109 / 106 | 0 / 0 | 9 |
| 813/002 | 806 / 803 | 539 / 0 | 21 |
| 925/012 | 674 / 670 | 2,902 / 57 | 15 |
| 925/016 | 383 / 379 | 1,665 / 410 | 6 |
| 925/020 | 1,144 / 1,140 | 2,336 / 387 | 25 |

计数覆盖元件库，含未使用的画法，不是主镜头可见元素或已成功播放帧数。各例有图形单帧/循环/播放一次模式、反射矩阵和不等轴长矩阵。非零非对角项也可能来自旋转，没有据此统计“斜切数量”。925/020 另有一个 camera 图层。场景 XML 本轮未找到非空 script/Actionscript 节点，不代表全部素材没有脚本。

可定位的实例：

- 813/002 的 `~PTS_Character`，索引 23 的 `TS*Tail` 图层引用 `PTS_Neck`；索引 25 的前腿名称图层引用 `PTS_Mane`、`PTS_ManeBit`。
- 925/016 的 `~SK_Character` 保存 698 帧、`~DCD_Character` 保存 465 帧，主镜头为 459 帧。要解析父子取帧，不能把元件全部帧当镜头实例。
- 无序实际含狮/鹰前肢、山羊/蜥蜴后肢及两种翅膀的引用；925/020 有 Duplicate Items Folder 中的替换部件。
- 提雷克 `new~TrF#3_Character` 含 Arm、Hand、FrontLeg、HindLeg、Torso_Upr、Torso_Lwr。结合预览，需两臂四腿定义；不适用现有示例混合身体的四肢结构。

脚本初版把非场景的 `MobileSettings.xml` 也送入 XML 解析，遇到声明 UTF-16 而实际为单字节文本的编码错误；`META-INF/metadata.xml` 还可能为空。修为仅解析 DOMDocument/LIBRARY，并把其余条目记录在 `non_scene_xml` 后，五个代表工程重新完成。没有改源 FLA、忽略场景错误或把元数据问题说成工程损坏。

## 接口核对与建议

检查 `scripts/common/multispecies/records.py`、`library.py`、`training.py` 与 `data/meta/body_catalog_v2.json`：

- 有图片、角色出现、工程完整性及审核字段约束；完整工程证据须绑定当前图片和出现、帧号、六项变换。
- 还没有 `alignment_ref` 的实际登记/解析器、FLA 导入器或播放还原器。字段验证通过不证明对齐事实为真。
- 能复用多物种方向与修订接口，但不能绕过必需图片，把整个 FLA 当一份姿态。
- 身体定义可扩展；无序示例结构仍需实际校准，提雷克需专用结构。
- 训练支持镜头/素材族联合分组及同图/同出现关联；清单提供补组入口，不自动认定素材族或补齐旧数据。

本次工具清单没有可调用的 Animate MCP。相邻项目 README 记载原生验证未完成、未接日常 MCP；离线源码存在不等于任意帧状态可读取。本轮未启动该项目的暂停测试。

已核对的经验为 KB-000009（容器读取边界）、AN-0010（实际标题为转身/鞍包挂接案例，包含内部命名和子时间轴证据）、KB-000010（原生头部导出）。按条件参考，未从单例推出通用批量渲染能力。

建议已写入方案：先素材目录，接着 20—30 个状态的小批方向验证，最后工程检索与训练规模实验。没有新增用户待办，也未把建议写成人已批准的实施。
