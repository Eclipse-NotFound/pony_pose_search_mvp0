# 2026-10-12 M10 原生工作台与启动修复

## 用户决定与问题

用户反馈 `run_m10.bat` 显示 Python not found，并明确选择“工作台功能直接整合进 M10 的 UI”。本轮按原生 Tk 控件实现，不嵌浏览器、不将打开网页当成完成整合。

已复现旧启动器错误：其仅尝试 PATH 中的 python / python3 / py。两个实际存在的 Python 都能导入 Pillow、初始化真实 Tk；系统命令路径未能发现它们。没有安装 Python 或修改系统 PATH。

## 实施

- `scripts/launch.ps1` 为两个 BAT 共用的解释器发现与能力检查入口，支持项目环境、安装登记、常见安装位置及已有 bundled runtime。路径和参数分别传递；解释器位置带空格时也按可执行文件路径调用。
- `scripts/m10/control_center.py` 增加主标签页，原生工作台为默认页，原 M01—M09 和 AI 面板保留在第二页；支持独立测试库和真实 UI 初始化检查。
- `scripts/m10/native_workbench.py` 提供素材列表、后台队列、取帧、角色框、方向绘制、审核／历史、角色形态、搜索结果、原画面／文件位置、CSV/JSON 和训练快照。短片预览为窗口内最多约 6 秒、10 fps、无声上下文预览，精确位置仍以静态帧为准。
- `scripts/m10/workbench_model.py` 复用现有 Library、SourceCatalog、SourceService、revise、search；保存仍走不可覆盖的修订与并发检查。原生结果导出固定当前结果和标注版本，不在导出时悄悄重跑排序。
- 原正式标注、模型及原素材没有被用作写入测试目标。所有测试记录及缓存位于 `experiments/m10_native_20261012/`。

3. 最终回归：`tests/m10/test_native_workbench.py`、`tests/m10/test_m10.py`、`tests/multispecies` 共 **138 passed，23.34 秒**。覆盖真实 Tk 控件、导入裁剪来源、方向编辑审核、未知部位、参考点失效、未保存保护、历史只读、并发冲突、失败重试、搜索结果来源、导出选项和旧 M10 纯函数；过程使用隔离目录。新增 `set_excludes` 支持清空排除项且不扩大原先只选特定文件的扫描范围，有回归断言。输出来自本次工具调用，未另存整段终端日志。

## 限制及验证中发现的情况

- 目录排除配置、搜索按格式／目录过滤及训练导出高级开关已提供原生窗口；新开关默认值与浏览器版一致。
- 原生测试直接使用 Tk 按钮和事件处理器，未将内部事件测试声称为系统鼠标人工验收。真实文件管理器是否最终选中指定文件，本轮没有做可见回读；原生按钮复用已有经内容校验的定位实现。
- 测试多次创建、销毁独立 Tk 解释器时出现 Tcl 脚本加载失败；单独启动与同一解释器下的窗口均正常。测试夹具改为共用一个 Tk 生命周期。没有据此断言本机 Python 安装损坏。
- 窗口截取脚本一次缓存旧窗口句柄后抓取失败，并出现已销毁 Tk 变量的后台回收提示；检查脚本改为每次重新取本测试窗口句柄，关闭预览后在主线程回收，再取图成功。这是检查过程证据，不据此声称修复了一个已确诊的生产故障。
- 本机两个解释器均未安装 cv2；M10 主窗口和新工作台不依赖它。原有模型训练／部分 AI 工具的整套环境未在本轮安装或验证。
- FLA 工程画面渲染与实例精确跳转仍未实现。本轮没有新增方向标签或进行模型训练。
- 共享经验检索返回 partial：一份登记来源不可读；没有把这个缺口当成“没有相关经验”。已读取本项目数据规则复盘的原件，当前代码与实际运行作为本轮结论依据。
