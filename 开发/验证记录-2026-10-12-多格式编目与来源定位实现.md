# 多格式编目与来源定位：首版实现验证

2026-10-12。用户在详细规划与交互预览后要求“进行代码实施”。本轮实现 A—D 的主流程：混合素材编目 → 视频/图片画面 → 单角色观测 → 原有方向标注/搜索 → 命中来源定位。FLA 纳入文件编目与可读结构；E/F 的工程实例对齐、原生精确跳转和工程方向训练仍未实施。

## 实际改动

- `scripts/common/source_catalog/`：独立 SQLite 目录、来源版本、精确画面、可恢复队列、格式读取、角色裁剪导入、定位与旧记录报告。未把旧姿态 JSON 全部搬进数据库。
- `scripts/m11/pose_workbench.py` 及 `web/sources.js`、`sources.css`：真实素材库、任务状态、前后逐帧、角色框、来源面板、结果筛选/复制/导出、附近播放与改绑目录。原有 `app.js` 接上来源展示，既有评分模块未修改。
- `scripts/common/multispecies/records.py`：校验新来源的位置引用、内容版本、角色框与裁剪坐标变换；旧记录继续可读。
- `scripts/m12/catalog_sources.py`：与网页共用实现的登记、队列、查询、取帧、改绑和导出命令入口。
- [用户说明](../docs/source-catalog.md)、README、工作台说明已接续；无需新增数据库服务。

内容版本由实际文件内容校验值确定。取帧前后及文件定位前核验版本；不同内容的同名文件分开，同内容的不同位置也保留各自文件身份。帧位置保存流编号、实际解码序号、PTS、时间单位、起始时间基准与解码器版本；显示序号从 1 开始。PNG 画面和裁剪图另外校验。旧采样序号不升级为原视频帧。

导入先保存派生图与稳定观测编号，再提交来源绑定，重试及重启沿用原编号；搜索只读完整提交的导入。多个角色可从同一画面建立独立观测，新记录不产生方向或审核结论。文件级分组和同内容分组用于保守隔离后续训练数据，不冒充经过人工确认的镜头/素材族语义。

队列单进程持有工作锁；扫描先登记再后台读取。交互取帧/播放优先于批量探测。正常关闭时终止本次媒体子进程、留下可重试任务；操作系统强杀后的已领取任务在下次取得工作锁时重新排队。暂停在检查点生效，不在半份内容上提交完成结果。

## 自动检查

最终相关范围 **338 passed，1 deselected**，见 [pytest-release.txt](../experiments/source_catalog_20261012/pytest-release.txt)。其中新增 **29 项来源检查**，覆盖：

- 混合文件、未知/损坏文件隔离、重复登记、所选文件范围与排除目录。
- 非标准 FLA 本地 ZIP 记录的长度、解压上限、CRC 校验；损坏文档明确失败。生产读取不依赖技能目录的绝对路径。
- 同名异内容、同内容异路径、文件更新、同大小/时间被换内容、处理中源文件变化。
- 原文件离线后仍保留缓存；根目录搬家全部匹配后提交，同名不同内容拒绝改绑。
- 角色框边界、EXIF 旋转后裁剪、像素比对、两个角色记录、重复导入不回退已审核修订、跨存储中断恢复。
- 实际生成并解码的变帧率/非零起点/多视频流样本；指定帧颜色核对、缺失/重复时间戳不混淆序号、越界拒绝、附近播放时间基准。
- 暂停持久化、重启回收任务、交互任务优先、停止时媒体子进程退出。
- 同一候选集合下评分完全一致；来源过滤在 top N 之前生效；旧秒数不冒充精确帧。
- 真实本机 HTTP 的会话/来源限制、帧读取、幂等导入、搜索结果、CSV/JSON、媒体分段请求和登记路径解析。文件管理器调用在该测试中替换为记录参数的函数，没有弹出系统窗口。

范围：`tests/multispecies`、两个公共记录/查询模块、M06/M07/M08/M09、`tests/m10/test_m10.py`。只排除 M10 原生窗口默认值检查 `TestPoseVectorVersion::test_default_is_v1`，当前运行时缺 Tcl；M06/M08 同名默认值测试正常参与通过数。

另有一次扩大到整个 M10 目录的检查：[pytest-final.txt](../experiments/source_catalog_20261012/pytest-final.txt)，结果 **411 通过、49 失败、3 剔除**。49 项失败均是旧 AI 审核流程导入 `cv2` 时当前环境缺少 OpenCV，不计为通过，未为本轮修改系统/训练环境。最终相关范围日志与这份扩展失败日志分别保留，没有宣称全仓检查通过。

Python 3.12.14、Pillow 12.3.0、FFmpeg/ffprobe 9.0.1；pytest 使用项目已有隔离依赖。8 个本轮相关 Python 文件语法通过，两份工作台 JavaScript 语法通过。CLI 实际导出 [目录快照](../experiments/source_catalog_20261012/catalog-export.json) 与 [实验库旧来源报告](../experiments/source_catalog_20261012/test-library-legacy-report.json)。

另一次受限执行环境的单项播放偏移检查未发现 WinGet FFmpeg（该环境的本地应用目录与正常本机不同），失败日志保留为 `pytest-proxy-offset.txt`。最终完整相关范围在实际能使用 FFmpeg 的本机环境执行，包含“非零源起点对应播放偏移 0.5 秒、播放副本起点为 0”的断言，以及 UTF-16 工程 XML 声明拒绝检查，均已通过。

## 仍未验证或未实现

- 没有本轮全量导入约 52.95 GiB / 15486 个文件，也未给全库吞吐、磁盘占用或大批量错误恢复作性能承诺；本轮真实读取抽样为 9 份，其他边界使用独立夹具。
- Windows 选中文件接口已实现并核对调用路径，尚未回读文件管理器实际选中状态；浏览器拖框使用真实事件处理器，但本轮角色区域操作主要通过坐标输入完成，没有真人触屏或物理拖拽体验结论。
- 原文件变化、根目录改绑通过隔离文件实测；没有挪动用户原素材制造测试条件。
- FLA 仅读主文档的存储结构，不解析每个嵌套实例的可见播放状态；不支持 Animate 精确跳转，也未生成工程方向或新训练模型。
- 旧原生 AI 审核界面的 OpenCV/Tcl 运行限制如上，没有用网页成功代替原生界面实测。
- 没有用户真人验收或检索质量提升结论。后续可从 E 的小镜头工程对齐接续，现阶段用户可直接使用 A—D 的视频/图片流程。
