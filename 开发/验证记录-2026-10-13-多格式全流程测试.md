# 不同格式素材编入—搜索全流程实测

2026-10-13。用户授权测试不同格式的编入、角色标注、搜索及素材位置返回，并允许代理自行标注。测试使用独立库 `experiments/format_e2e_20261013/library-final`，真实原素材只读。没有写入正式标注或正式模型。

## 结论

**PNG、JPG、WebP、MP4、MOV、MKV 的完整流程通过**：导入／读取 → 候选 → 角色框 → 裁剪样本 → 方向标注与测试审核 → 保存查询 → 按格式／身份搜索 → 找回原文件及图像／视频帧 → 导出 → 关闭重开。

**FLA、XFL、SWF 的能力边界通过检查，尚不能直接生成姿态供检索。** 现代 FLA 可编目和读主文档结构；旧 FLA（OLE）及 SWF 可文件编目。配套 JPG／MOV／MP4 的搜索结果会返回同名 FLA 候选，但没有提升为已对齐的工程帧或实例。XFL 使用从真实 FLA 提取主文档的辅助夹具，不代表完整工程渲染实测。

已修复两个实际影响导入的界面问题：候选不在当前页时无法选中；已有标注被选中时，新生成样本被刷新事件切回旧标注。两个用例修复前均失败，修复后通过。

[标注与测试 HTML](../experiments/format_e2e_20261013/report.html)展示角色、方向箭头、格式矩阵和程序实际导出的搜索结果。[原生检索截图](../experiments/format_e2e_20261013/m10-format-results.png)、[返回 MOV 原画面截图](../experiments/format_e2e_20261013/m10-format-source.png)已目视核对。

## 发现、修复及保留日志

1. **分页候选无法选中**：建立 102 个候选、让目标处在另一页，原 `save_candidate` 直接在当前树列表选中 ID，出现 `Item … not found`。新增集中定位操作，先算目标所在页、刷新、选中并加载画面。见 `pagination-red.log` 和 `test_save_candidate_focuses_the_correct_page`。
2. **新样本切回旧记录**：已经有当前查询/记录时，生成回调先刷新列表，再载入新样本；旧选择事件稍后执行，重新载入旧记录。样本保存成功，但编辑器留在旧对象。现在 `load_record` 同步列表选择；不在当前过滤列表时清除旧选择。修复前“导入后有两条记录，但仍编辑第一条”用例失败；见 `import-red.log` 及 `test_import_after_existing_selection_keeps_new_record_loaded`。
3. **测试脚本身份复用失误**：首轮辅助函数按形态标签找角色，而自动形态标签附带后缀，导致麦托什 JPG 和 MOV 被建立为两个身份。按角色身份及结构复用后，在新库重跑，111 项全部通过。首轮 `first-flow-result.json` 和 `first-flow-run.log` 保留；这不是程序身份筛选算法错误。
4. **测试夹具状态收尾**：冻结导出检查故意改反一个方向，在第一次 UI 检查中影响 MKV 的可用标签；追加修订恢复了实际视觉标注，再完成六种格式 UI 流程。见 `restored-test-labels.json`。再次运行脚本时已有显式恢复步骤。
5. **Tk 组合测试偶发收尾问题**：第一次原生整组回归有 1 项超时，并出现旧 Tk 变量在后台垃圾回收时析构的线程警告。测试夹具在开启下一后台窗口前，于主线程回收已销毁对象；同一原生范围重跑 12 passed。保留 `pytest-native.log`，不将首轮失败计为通过，也不据此宣称所有后台线程边界都已验证。

诊断使用 `diagnosing-bugs` 2026-10-08.1；两个业务错误通过原始流程和小复现核对后修复。技能短回执位于工具区测试报告目录，业务证据留本项目。
