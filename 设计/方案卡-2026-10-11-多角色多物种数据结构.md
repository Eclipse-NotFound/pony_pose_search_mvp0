# 多角色、多物种数据结构设计

日期：2026-10-11。状态：**用户已要求实现；方向优先的数据层、独立多物种工作台与旧资料迁移已完成。原流程保留，新物种语义仍待实证。** 使用入口与实际实现边界见[工作台说明](../docs/pose-library-v2.md)，测试证据见[实现验证记录](../开发/验证记录-2026-10-11-多物种工作台实现.md)。下文保留设计原理，设计样例不作为真实标注。

用户希望扩展更多角色与物种，并明确优先覆盖小马、狮鹫、龙和混合身体角色。零基础阅读入口：[交互图解](../docs/multispecies-design/index.html)。机器可读目录、5份合成样例及迁移映射：[design-bundle.json](multispecies-v2/design-bundle.json)。本文给实现者提供完整约束。

## 1. 目标、现状和设计取舍

目标是让不同身体结构共用同一套记录与审核流程，并在含义一致的部位上检索。支持一种物种至少包括结构可表达、标注规则可执行、模型输出可映射、比较范围明确；增加一个物种标签并不等于这些能力已经完成。

当前 `pose_record_v1` 已分离身份和形态，但验证器要求恰好14方向，转换仍统一写 `pony_quadruped`，匹配器要求身体类型相同并使用固定前腿2段、后腿3段规则。它适合现有小马数据，不能直接装入任意物种。

| 取舍 | 推荐设计及后果 | 反转成本与未验部分 |
|---|---|---|
| 一套巨大通用骨架 / 每物种完全独立 / 模块组合 | 选模块组合：方向记录统一，身体说明书不同；共享规则只定义一次 | 需要版本目录和引用校验，比固定14项复杂；改变模块含义必须出新版本 |
| 物种直接决定骨架 / 独立身体结构 | 物种只作身份与筛选标签，形态引用结构 | 同一种龙可有多种身体；不能仅凭物种自动补肢体 |
| 任意向量强配 / 显式比较约定 | 只有已确认对应含义的方向参与同一口径评分 | 默认跨结构召回更保守；新物种的对应规则需要素材实证 |
| 一次覆盖旧库 / 新副本逐步验证 | 原标签保留，新格式独立生成并逐方向对照 | 暂时有两个入口，成本是维护适配器；可以回退而不丢标签 |

沿用用户决定：方向为主，视角和少量位置辅助；点位可选；尾巴只取初始朝向；镜像默认关闭；默认允许同类整腿交换并保留身份；对应图层有可取得的完整角色即按完整处理。新设计把“同类”落实为有兼容分段含义的整肢，不自动交换结构不同的混合肢体。

## 2. 可复用资料：谁、哪种形态、什么身体

建议目录与标注分开存，先沿用 JSON/JSONL，不引入新的数据库依赖。下表是逻辑实体，不要求立即建立这些物理表。

| 实体 | 必填身份与关系 | 内容与约束 |
|---|---|---|
| Character 角色 | 稳定 `character_id` | 名称、别名；同一角色变形后身份仍可保留。匿名角色允许没有角色引用，不能全部写成同一个“unknown”实例 |
| Species 物种标签 | `species_id` | 展示名称、可选父标签；只用于筛选，不根据分类继承骨架或动作规则。混合/未知可明确记录 |
| Form 形态配置 | 版本ID、角色引用可空、物种引用可空、结构引用 | 某种形态采用哪份结构、通常有哪些部位/特征。不要同时把同一事实复制到角色、形态和姿态三个位置当正本 |
| Module 部位模块 | 带版本 `module_id` | 局部方向定义、参考点规则、可选辅助量定义。每个方向有稳定局部键及明确起止语义；段数相同不代表兼容 |
| Profile 身体说明书 | 带版本 `profile_id` | 部位槽位到模块的组合、可选部位、整肢交换组；可以有任意数量的肢体，不要求左右成对 |
| Comparison contract 比较约定 | 带版本ID、成熟状态、双方结构投影 | 规定比较语义、方向映射、组权重、交换约束、可用的视角和位置定义。只比头和比全身是不同约定 |

角色ID不含物种或形态后缀；旧 `twilight_unicorn` 保留为别名/历史映射。目录版本不可就地改含义，引用精确版本并可附内容指纹。形态资料的通常配置可以帮助预填，但实际记录必须有确认状态与依据；不能把先验当作观测。

### 结构如何扩展

- 小马：原主干4方向、两前腿各2、两后腿各3，保留14方向。翼作为可选模块，不改变旧身体方向名称和意义。
- 狮鹫：主干、两前肢、两后肢、两羽翼分别组装；示例暂用18方向。爪与兽形后肢的具体分段是草案，不声明等同于小马腿。
- 双足有翼龙：头颈、骨盆到肩的躯干方向、尾根、两手臂、两腿与两膜翼；示例18方向。双足躯干轴不能冒充小马“前躯到后躯”的轴。同一物种的四足龙应另配结构。
- 混合身体：弯曲躯干可分多段，两侧前肢/后肢/翼可以不同；示例19方向。不为了满足“每组恰好两条同构肢体”丢掉差别。

上述新物种的分段数是设计示例，不是正式标注标准。数量只随模块定义确定，不从名称或视觉常识猜出。角、耳朵、服装等没有进入当前检索目标的特征可作为形态属性；以后确需检索其姿态，再定义对应模块，不预填大量无用空方向。

## 3. 每次观测：实例、图像、坐标和原素材

一条原子观测绑定**一次出现中的一个角色实例＋一张具体图像**。同一实例的成片裁剪与单独工程导出可以各有观测，通过 `occurrence_id` 和核对过的时间/实例对应关系相连。不能直接混用两张图的像素点。

| 字段 | 类型 / 可空性 | 含义 |
|---|---|---|
| `observation_id` | 稳定字符串，必填 | 一张图中的一次角色观测，不由整个标签文件的hash决定 |
| `occurrence_id` | 稳定字符串，必填 | 同一来源时刻的某个角色实例；重影/克隆也各自编号 |
| `subject.character_ref` / `form_ref` | 引用或null | 能确认才填；角色未知但结构清楚也可以标注与检索 |
| `subject.track_ref` | 引用或null | 经确认的跨帧轨迹，不凭角色名字或相近时间自动建立 |
| `profile_ref` | 精确版本引用，必填才能入姿态索引 | 能独立于角色身份确定；若有已解析形态引用，两者必须一致 |
| `image_ref` | 图像资产引用，必填 | 实际模型或人工所见的图，不只存可能被覆盖的文件名 |
| `coordinates` | 坐标对象，必填 | 图像二维、右/下为正、宽高；可选到原帧的变换及变换依据 |
| `source` | 来源对象，必填 | 媒体资产、场景、绝对帧号、帧率分数、工程实例路径与时间对齐依据；未知字段为null |
| `split_groups` | 镜头/复用素材族引用或null | 训练评价按组切分；未知不伪造，不把相邻帧当独立样本 |

图像资产目录至少包含路径/URI、内容SHA-256、尺寸、种类、原媒体引用。内容改变产生新资产版本；本机迁移路径不改变内容身份。FLA、Review视频和最终剧集可有不同时间轴，需显式对齐记录；帧率用分子/分母以避免小数误差。提取方法、工具版本和坐标变换归证据记录。

当前范围只承诺二维图像方向。旋转、缩放、翻转后必须根据定义重算单位向量；非均匀缩放会改变方向。工程的角度属性不能直接代替最终画面方向。未来3D应另设坐标空间和定义，不把二维缺信息伪装为三维。

## 4. 部位存在、方向判断和审核彼此独立

`annotation.parts[slot]` 存 `presence=present/absent/unknown`、存在性依据，以及可选身体左右、镜头近远、工程路径等身份。存在性也是标注判断，随方向一起保存不可变修订；后来确认有翼时，不能倒改旧版本的“未知”。未知存在性须记录原因。槽位A/B不等于左/右/近/远；旧腿1/2迁移成A/B且身份保持未知。

| 部位状态 | 方向记录要求 | 对检索的影响 |
|---|---|---|
| 确认存在 | 该模块每个方向都给一个条目，未知也写原因 | 不能靠漏字段让难判断的方向消失 |
| 确认不存在 | 不创建该部位方向条目 | 请求明确需要该部位时不适用；仅搜共用身体时无影响 |
| 是否存在未知 | 不捏造方向，保留部位未知状态与原因 | 覆盖不足；不当作确认无此部位 |

每个 `annotation.directions[slot.local_key]` 包含：

| 字段 | 约束 |
|---|---|
| `value` | `[dx,dy]` 或null；两数有限、长度约1，零向量无效。只记录单位方向，不存箭头显示长度 |
| `missing_reason` | 有值必须为null；无值必须说明未标、不可辨、遮挡、画面外、工程未画、几何无效或旧记录未说明 |
| `visibility` | 当前图中可见/遮挡/画外/未知；不能以工程可取得性覆盖图像可见性 |
| `evidence_refs` | 至少指向一个存在的依据；逐项允许来源不同 |
| `confidence` | 经校准的可信度或null；训练样本权重不是可信度 |
| `review_status` | 未审/通过/修正/拒绝/旧正式身份；逐项保存，格式迁移不提升审核级别 |

观测下面的 `annotation` 是不可变修订：稳定ID、父修订ID列表、部位存在性与身份判断、方向、可选点位、视角、位置。改动写新版本；引用父版本继承的项目应可追溯，不能“审核了前腿”就把全身变成已审核。审核事件补充审核者、时间、所覆盖方向/部位键、结论和备注；允许批量审核，但保存覆盖范围。实际实施时可以把修订和审核事件单独写JSONL，示例包为阅读方便放在观测旁。

`reference_points` 可省略，其坐标体系必须与所绑定图像一致。点推导的方向保留推导规则与点位修订引用；直接模型/工程方向不要求伪造点。人工改点重新派生属于新修订，不悄悄覆盖来源。

## 5. 完整工程角色的准确落点

记录 `asset_access.complete_character=verified/unavailable/unknown` 及证据引用。verified须能定位对应工程、实例、时刻和查看/导出依据；证据的范围应覆盖这份结构所期望的完整角色。仅见到“腿”元件名不能确认完整。

满足用户规则时，已取得且有工程依据的隐藏方向与可见方向都可参与检索。还未提取出来的方向继续缺失，不能由 complete 标志生成数值。成片与角色单独导出各有图像观测；要训练直接从无遮挡图读方向，应配单独导出的角色图。若用遮挡成片预测隐藏方向，应另设明确的遮挡推断实验任务。

## 6. 跨物种检索：比较约定、兼容和覆盖

检索请求至少携带：

```json
{
  "query_annotation_ref": "a stable revision id",
  "comparison_contract_ref": "pony.body14@1",
  "filters": {"character_refs": [], "species_refs": []},
  "allow_mirror": false,
  "allow_whole_limb_exchange": true,
  "include_unreviewed": false,
  "candidate_missing_policy": "fixed_query_denominator",
  "minimum_coverage": null
}
```

minimum_coverage为null时仍完整报告覆盖度，不假装已有经过验证的门槛；生产界面应把明确的门槛与评分策略版本写进运行记录。

1. **筛范围**：角色/物种筛选与身体兼容判断分开。身份未知但结构可用的图可以在不限定身份时参与。
2. **确认语义**：相同模块精确版本可直接映射；不同模块必须有显式、已确认的比较约定。模块都是2段不意味着两段意义相同。草案映射只供隔离试验，不进入正式默认检索。
3. **形成固定查询口径**：先选本次要比的方向与查询已知项。全空查询拒绝。候选缺方向不从分母中消失。请求全身但只拿头来比时，必须另标为部分匹配，不能并入全身排名。
4. **整肢配对**：只在说明书和比较约定共同允许的兼容组内一对一配对；全部分段一起移动。一条候选不能重复使用。严格身份模式另选，未知身份不得假装已核实匹配。
5. **评分与覆盖**：返回方向得分、查询指定项中有标签的比例、候选满足查询已知项的比例、结构不适用项、辅助项实际数量。权重按部位预算分配，部位多不自动拥有更多权重。不同约定的分数不直接混排。
6. **辅助信息**：视角与布局都有定义版本。只比较相同含义、相同归一化参照的量，缺失跳过并报告覆盖；仍以方向为主。不能把小马轴长和双足龙轴长无标记地等同。
7. **可选镜像**：候选整体翻转再比较，保留最佳变换与配对；分数持平优先原图。方向与布局同步变换，原标注和身体解剖身份不改写。

推荐的首批约定：小马身体14方向（翼不计入，沿用已知语义）；跨物种仅头部朝向（待实证）；羽翼局部姿态（待实证）。双足躯干与四足躯干、羽翼与膜翼、异形肢与小马腿的全段对应均不默认存在。用用户可用素材的实际结果决定是否新增更宽的动作类对应，而非为了凑相似度硬映射。

## 7. 多模型、训练和索引

模型能力清单声明支持哪些结构版本、输出哪些方向定义、输入图像预处理/坐标变换、训练标签版本和未覆盖部位。一个模型可以输出多个模块，也可以先分模型识别；数据结构不强制“一个万能模型”。直接方向与点位模型输出到同一语义入口，比较时保留推导路线。

索引是从被允许的标注修订和比较约定派生的缓存，保存这些输入及配置的指纹。词典、标注、映射或权重变动后失效重建；缓存不能当作标签正本。缺图、纯色图、文件内容更换必须能在数据检查中发现，沿用上轮实际问题的教训。

训练集快照冻结：观测ID、所用方向/存在性项目、标注修订、审核范围、原图SHA、训练权重、分组切分、生成器版本。按镜头和复用素材族防止邻帧或相同动画模板泄漏；分别报告物种、结构、部位表现。实际检索“前几名是否有可用素材”另评，不能用平均方向误差替代。

## 8. 版本、迁移与验证

需要分别版本化：保存格式、身体/模块语义、比较约定、模型、某次标注修订。更改标签名称可加展示别名；改变方向起止、分段数量、参考尺度必须产生新语义版本并显式适配。未知对应保留旧版，不强制转换。

旧 `pony_body14_v1` 按设计包的14项一对一映射迁移，浮点方向保留原值；旧null保持旧原因；腿1/2变槽位A/B但不补近远侧；图像坐标、审核来源、FLA可取得性原样保留；不得用新的形态先验补出翼姿。当前格式的整标签文件指纹仍作为证据，不能再拿它决定所有观测的稳定ID，否则修改一张图会令整批ID一起改变。

迁移先生成独立副本，对照小马每方向、原排名和缺失处理；再加入新的结构与人工规则样例。先验证表达与标注一致性，再比较模型，最后验证用户检索收益。

本次设计检查：5份合成样例（14/18/18/18/19方向）、完整14方向旧键映射、目录引用与单位向量、7种故意错误的拒绝检查。结果在 [validation.json](../docs/multispecies-design/qa/validation.json)。该检查是示例一致性检查器，不是覆盖全部约束的正式JSON Schema或生产迁移程序。

实现接续：已提供版本目录、格式与引用验证、追加修订存储、逐项审核、按模块生成的标注界面、比较约定执行器、训练快照和模型输出适配器。已迁移原正式、实验和查询记录，保持审核来源与原方向值。相对位置沿用旧小马定义；几何改变时清除过期位置，新物种位置辅助规则尚未接入。

仍待实际素材验证：新物种方向画法、跨物种对应、工程对齐及提取；仍待训练与评价：新物种模型、方向与关键点路线的公平对照、实际检索收益。当前不会因为结构可标注就宣布这些物种已经自动识别可用。
